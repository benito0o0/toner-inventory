# 碳粉庫存

沿用原有 GitHub Pages 專案的手機優先庫存網站。品牌 → 設備型號 → K 黑／C 青／M 洋紅／Y 黃，各色獨立計算。單色型號僅 K，四色型號包含 K／C／M／Y。

## 本機開發

Node.js 18+，執行網站及單元測試不需要安裝外部套件。

```sh
npm test
npm start
```

預設連接埠 3000，`PORT` 可覆寫。修改 `inventory.js` 或 `apps-script/backend.gs` 後執行 `npm run build:apps-script`，產生可貼入 Google 的 `apps-script/Code.gs`。GitHub Pages 直接載入靜態檔案，無需執行 Node 伺服器。

## 功能與儲存

- 首頁透過品牌篩選與型號搜尋，每次只顯示一個設備型號。操作或背景讀取不會任意切換選取的型號。
- +1、+2、−1、−2 先在本機暫存；正式儲存成功才更新試算表與異動紀錄。零庫存仍保留品項；不足時停用減少按鈕。
- 設定區新增品牌與型號、初始數量及門檻；相同品牌／型號不可重複（忽略大小寫、頭尾空白及字元寬度）。數量與門檻限制為 0 至 1,000,000,000 的整數。
- 庫存小於或等於門檻顯示提醒。門檻修改也檢查品項版本，但不產生庫存增減紀錄。
- 首頁顯示最近五筆，歷史區保留全部紀錄，以臺北日期、品牌及型號篩選，每頁二十筆。
- 設定區可匯出正式庫存 CSV、全部異動 CSV，或含完整共用資料與本機暫存的 JSON 備份。離線匯出只反映最後成功讀取的資料，備份附有讀取時間。

共用庫存儲存在 Google 試算表，前端 localStorage 僅保留部署網址、待儲存增減及待確認的操作 ID。沒有共用服務時不會冒充已同步，也不會自動改用獨立本機庫存。

## GitHub Pages 與 Google 串接方案

GitHub Pages 沒有後端。Google Apps Script 綁定試算表、以擁有者身分執行並允許任何人存取。前端內嵌 HtmlService 橋接頁，使用限制來源的 postMessage 與 google.script.run 呼叫伺服器，避免以 `no-cors` 寫入而無法確認結果。Apps Script 橋接尚需在真實部署驗證；瀏覽器設定或組織政策可能阻擋匿名嵌入。

每 **15 秒**讀取共用資料，回到頁面時也會讀取。這是定時同步，非真正即時推送；背景分頁、網路及 Apps Script 配額可能延後更新。

免登入的限制：取得部署網址的人可能讀寫全部庫存，無法辨識操作者、無使用者角色權限，網址與來源檢查不是身分驗證。不得將此模式用於需要嚴格授權的資料；需那類限制時應改用身分驗證後端。試算表本身不需設定公開分享。任何 Google 憑證、OAuth token、服務帳號私密金鑰都不可放在公開前端或儲存庫。

### 交易與同步

所有讀寫使用同一個 ScriptLock，逐一處理交易。品項包含版本，儲存時檢查所有變更品項的版本與非負庫存，任何一項失敗則整筆不生效。不同品項可獨立儲存；同品項有衝突時要求核對最新數量後重新套用增減，或取消本機暫存。背景更新不會清除本機暫存。

每筆操作在送出前將唯一 ID 和完整內容存到本機；後端永久保留已接受操作的 ID 與內容。逾時、回覆遺失或重新開頁後，重試相同操作只取得既有結果，不重複扣庫存或記錄。在結果尚未確認時停用再次調整、新增與取消，以免產生第二筆相同操作；若伺服器明確拒絕則可修改或取消。實際網路錯誤不會顯示儲存成功。

正式資料以壓縮交易快照保存在「系統交易資料」工作表，完整庫存、紀錄與操作 ID 一起提交。先寫入快照並確認，再更新 A1 單一指標；未提交的快照不生效。SHA-256 校驗失敗時停止讀寫，絕不初始化覆蓋。舊快照不刪除，可作為擁有者復原依據。「庫存檢視」與「完整異動檢視」是方便閱讀的衍生表；若更新衍生表失敗，正式交易仍以已提交快照為準並顯示警告。

請勿直接編輯或刪除系統交易資料，也不要直接改檢視表來調整庫存。長期使用會增加完整歷史、操作 ID 與快照大小，Google Sheets 容量及 Apps Script 執行／並行配額仍有限；此方案適用小團隊。沒有為了符合配額而截斷舊紀錄，達到限制時應備份並改用資料庫後端。

## Google 設定（實際操作可逐步進行）

1. 建立空白「碳粉庫存共用資料」試算表，保持私人，不先匯入各裝置數量。
2. 在試算表選「擴充功能 → Apps Script」。
3. 把 `apps-script/Code.gs` 的**完整內容**貼到編輯器的 `Code.gs`，儲存。
4. 左側「＋ → HTML」，命名 **Bridge**，貼上 `apps-script/Bridge.html` 全文，儲存。
5. 在函式選單選 `setup`，執行並以試算表擁有者授權。只授權你自己剛建立、看過程式內容的專案。它會記住試算表 ID 並建立系統與檢視表，不會清空既有工作表或交易。
6. 專案設定的指令碼屬性 `ALLOWED_ORIGIN` 預設為 `https://benito0o0.github.io`。如網站採自訂網域，改為實際網站來源（只有 scheme＋host，沒有路徑）；不要設 `*`。本機測試須另用測試部署及對應來源。
7. 「部署 → 新增部署 → 網頁應用程式」，執行身分選自己，存取對象選「任何人」，部署並複製 `/exec` 網址。若帳號政策沒有「任何人」選項，免登入模式無法部署，需管理員調整或另選後端，不要關閉安全驗證。
8. 在網站「設定與備份」貼入部署網址並連接。每台裝置第一次都需要連接同一個網址。網址是服務入口，不是 Google 憑證；可以分享給可信任團隊，請勿任意公開。
9. 更新後端時須在「管理部署」選新版本並更新同一部署。修改本機檔案或推送 GitHub 不會更新 Apps Script。

## 既有瀏覽器庫存遷移

原本 `toner-inventory.v1` 的 K／C／M／Y 不會刪除或覆寫。初次載入會複製到 `toner-inventory.v1.backup`（若已有備份不覆寫），首頁可展開查看原始庫存。

請在原本使用網站的同一裝置、瀏覽器與來源進入設定，匯出「此瀏覽器舊庫存」。各裝置可能數量不同，須先比較並確認採用哪一份；不會自行相加。可在另一裝置載入原始 JSON，畫面顯示每色數量；填入品牌／型號並勾選確認後，才會將這一份作為新型號匯入，留下明確的「舊資料匯入」紀錄。原始 localStorage 仍保留。已存在的品牌／型號禁止匯入覆蓋，請先核對實際庫存，勿為重複匯入而任意改名。

從不同網址或不同瀏覽器無法讀取原有 localStorage，必須回到原網站來源匯出。雲端開發環境也無法直接備份使用者手機裡的資料。

程式修改前的 Git 備份點為 `ec4694415974fe99b002fdbf936e492993490f34`。目前雲端另有 `/workspace/backups/toner-inventory-before-upgrade.tar`，這個檔案不包含使用者手機庫存。

## 驗證範圍

`npm test`：交易核心及模擬 Apps Script 執行環境，涵蓋新增、重複、非負庫存、零庫存保留、歷史完整保留、衝突、不同行為不互相覆蓋、冪等重試及快照提交失敗。

真實 Chromium 瀏覽器的額外測試（測試套件可安裝到獨立目錄，不加入網站依賴）：

```sh
npm install --prefix /tmp/toner-browser --cache /tmp/toner-npm-cache --no-audit --no-fund playwright
PLAYWRIGHT_MODULE=/tmp/toner-browser/node_modules/playwright/index.mjs node scripts/browser-smoke.mjs
```

需安裝 Chromium，預設 `/usr/bin/chromium`，可用 `CHROMIUM_PATH` 指定。瀏覽器測試使用兩個獨立工作階段及模擬共用服務，涵蓋手機排版、舊資料備份、匯入、暫存取消、零庫存、每 15 秒同步、他人更新保留暫存、同時儲存衝突、已提交但回覆失敗的重試、完整紀錄、重複建立及匯出。

**尚未驗證**：Google Apps Script 實際匿名部署、Google iframe 跨來源橋接、真實試算表配額／寫入、真實手機與 Google 服務之間的雙裝置同步。需擁有者部署授權後執行驗收，模擬測試不代表這些已完成。
